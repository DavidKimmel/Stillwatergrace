StillWaterGrace Reframe Design

Date: 2026-03-20  |  Approved

Goal: Simplify the content pipeline to one polished reel format, replace FFmpeg with Remotion, establish a unified cinematic visual brand.

Problem Statement

StillWaterGrace has accumulated too many content types, rendering paths, and visual styles. The result is 14 posts/week where none look professional. Three separate FFmpeg-based reel generators produce inconsistent output with white card overlays that don't match the cinematic aesthetic of successful faith accounts like @glorifyappofficial (462K followers) and @mightylordverses (82K followers).

Design Decisions

One Format, One Look

  • Single content type: daily_devotional replaces all 7+ active types (daily_verse, marriage_monday, faith_friday, encouragement, christian_quote, carousel, etc.)
  • 7 posts/week (1/day), down from 14/week (2/day)
  • Single posting time per day (to be tuned)

Visual Identity (Cinematic/Editorial)

  • Full-screen Unsplash imagery: nature, moody, cinematic color grading (warm tones, film grain)
  • Text appears directly on the image — no cards, no boxes, no overlays
  • Phrase-by-phrase or word-by-word captions synced to narration via ElevenLabs word timestamps
  • Clean serif typography in cream/white, positioned for readability
  • Subtle Ken Burns motion on background image
  • No watermark card, no Logo.mp4 outro
  • Target duration: 15-20 seconds

Reference Accounts

  • @glorifyappofficial — cinematic moody aesthetic, warm golden tones, B&W, film grain, text directly on imagery
  • @mightylordverses — dark backgrounds, clean serif text, minimal layout

Single Voice

  • Ian Cartwell (voice ID: e5WNhrdI30aXpS2RSGm1) — American English narration voice
  • No rotation. One voice = brand recognition.

Script Structure

  • Scripture-focused: a Bible verse with optional brief intro
  • Intro examples: "Scripture teaches us...", "In the Bible it says...", "The book of Psalms reminds us..."
  • Claude decides per-verse whether an intro adds value or if the verse stands alone
  • No forced hook structure
  • Bible source: api.bible (from ReelCreate, supports preferred translations like NIV)

Rendering Engine

  • New Remotion composition built from scratch inside SWG
  • NOT ported from ReelCreate — clean purpose-built implementation
  • Python renderer bridge passes props to npx remotion render
  • Input: Unsplash image, narration audio, word timestamps, music track, script text
  • Output: 1080x1920 MP4, 30fps

Technical Decisions

Audio Architecture

FFmpeg pre-mixes narration + music into a single audio file before Remotion render. Remotion receives one <Audio> track. This keeps audio mixing in Python/FFmpeg (where we already have working code) and simplifies the Remotion composition. Word timestamps are relative to narration start, which equals audio start (no offset — narration begins at frame 0).

Word Timestamp Contract

ElevenLabs eleven_v3 with alignment returns word-level timestamps. The renderer bridge passes these to Remotion as a JSON array of { word: string, start: number, end: number } (seconds from audio start). Captions are grouped into 3-5 word phrases for display. No offset adjustment needed since narration starts at t=0.

Remotion Project Location

Lives at rendering/remotion/ inside the SWG repo. It is a standalone npm package with its own package.json. The Dockerfile adds RUN cd /app/rendering/remotion && npm ci to install dependencies at build time. The npx remotion render command runs from this directory.

Database Migration

Migration 007: adds daily_devotional to the contenttype PostgreSQL enum via ALTER TYPE contenttype ADD VALUE 'daily_devotional'. Old enum values are preserved for historical data. No tables are dropped or modified.

Content Generator Output Schema

Claude returns JSON with these keys for daily_devotional:

  • narration_script — full narration text (optional intro + verse). This is what gets sent to ElevenLabs.
  • verse_text — the scripture text only (for caption display)
  • verse_reference — e.g., "Psalm 46:10 NIV"
  • caption — Instagram caption (verse + reflection + hashtags)
  • unsplash_query — search term for background image
  • music_mood — one of: peaceful, reflective, hopeful, reverent

The generator's REQUIRED_KEYS validation will be updated to match this schema. Old keys (hook, reel_script_15, reel_script_30, etc.) are removed.

Calendar Update

WEEKLY_SCHEDULE in calendar_logic.py is rewritten to 7 slots: one daily_devotional per day. The POSTS_PER_DAY_BY_WEEK ramp logic is removed — it's 1/day from the start. Provisional posting time: 6:30 AM EST (morning slot). Celery beat schedule reduced to one morning-post task. The noon-post task is removed.

Render Failure Handling

If Remotion render fails (Chrome crash, OOM, missing asset), the content stays in pending status with error logged. It does NOT auto-post. The dashboard shows the error — user can retry or skip. No FFmpeg fallback. This is acceptable because we review all content before posting anyway (AUTO_APPROVE=false).

Branding

No watermark card or Logo.mp4 outro. A subtle @stillwatergrace text in the bottom corner (small, semi-transparent) replaces the old watermark system. Instagram already shows the account handle on reels.

api.bible Integration

Port the bible_api.py client from ReelCreate which uses api.bible (API key required, supports NIV/ESV/KJV). This replaces the existing BibleAPIClient in core/scraper/bible_api.py which uses bible-api.com (WEB translation only). The existing bible_verses table schema is reused — just the translation field changes. API key goes in .env as BIBLE_API_KEY.

Other Technical Notes

  • Unsplash queries curated for cinematic look: golden hour, moody nature, dramatic skies, ocean, forest light
  • Remotion needs Node.js 20+ runtime — already in Dockerfile
  • Render tasks run on the existing Celery worker (no dedicated queue needed at 1 render/day)
  • Dashboard content-type display may need trivial update to recognize daily_devotional
